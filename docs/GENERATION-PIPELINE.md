# The generation pipeline

> **Status: draft skeleton.** The structure below is agreed; the specifics are not
> yet filled in. Every `TODO(maintainer)` marker is a fact that needs to come from
> someone who knows the pipeline, not from a guess. Until they are resolved, treat

Parts of this repository are **generated** from blueprints and other source-of-truth
files. Editing a generated file by hand looks like it works — until the next
regeneration silently reverts your change, or CI's drift check fails on a diff you
did not expect.

This page exists so that three things have somewhere to point:

1. **The CI drift check** — it regenerates everything and fails if the working tree
   changes. It needs to know the command and the paths.
2. **The "do not edit" headers** on generated files — they should link here.
3. **You, a new contributor** — so you can tell at a glance whether the file you are
   about to edit is one you own.

`app/dist/` is a **build artifact**, not a generated source file. `README.md`
documents it as the output of `npm run build` / `docker compose run --rm dev npm run
build`. It is produced on demand, is not reviewed, and should not be part of the
drift check. Keep the distinction sharp: *generated files are committed and
reviewed; build artifacts are neither.*

## How to tell if a file is generated

Every generated file should carry a header in its native comment syntax, pointing
back here. Proposed wording — `TODO(maintainer)`: confirm whether headers already

real text.

```yaml
# GENERATED FILE — DO NOT EDIT BY HAND.
# Source: <path to the blueprint this was compiled from>
# Regenerate: see docs/GENERATION-PIPELINE.md
```

If you find a generated file *without* such a header, that is a bug worth fixing —
the header is the only warning a contributor gets at the moment they open the file.

## The drift check

The intended CI contract:

1. Check out the branch.
2. Run the regeneration command above.
3. Fail if `git status --porcelain` reports any change.

A failure means someone edited a generated file directly, or changed a blueprint
without regenerating. The fix is the same either way: change the **source**, run the
regeneration command, and commit the result alongside the source change in the same
commit — so that reviewers can see the blueprint edit and its compiled consequence
together.

For this to be reliable, regeneration must be **deterministic**: no timestamps, no
unordered map iteration, no absolute paths, no version strings that move on their
own. `TODO(maintainer)`: confirm the compiler output is byte-stable across runs and
across machines. If it is not, the drift check will produce false failures and
people will learn to ignore it, which is worse than not having one.

## If you are adding a new generated output

1. Add it to the table above, with its source and its generator.
2. Emit the "do not edit" header as part of generation, not as a manual step.
3. Confirm the regeneration command picks it up — the drift check only protects
   paths the command actually rewrites.
4. Make sure a second run produces no diff.
