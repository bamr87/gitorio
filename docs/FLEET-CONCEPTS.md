# Two things called "fleet"

This repository uses the word *fleet* for two unrelated things. They have
different owners, different data sources, and different consequences when you
edit them. This page exists so you edit the right one.

## TL;DR

| | **wtd fleet manifest** | **Fleet Ops roster** |
| --- | --- | --- |
| Where it lives | [`fleet.manifest.yml`](../fleet.manifest.yml) at the repo root | Not a file in this repo — imported at runtime from a **hub repository's `.gitmodules`** |
| What it describes | *This* repository, to the outside | *Other* repositories, to the app |
| Who writes it | The `wtd` tool (`wtd fleet adopt`), plus hand edits | Whoever maintains the hub repo's submodules |
| Who reads it | `wtd` fleet tooling, outside this app | The Fleet Ops cockpit in the GitFactory frontend (`app/src/fleet/`) |
| Vocabulary | `fleet/v1` | Git submodule entries |
| Editing it changes | How `wtd` sees this repo | What the cockpit lists |
| Editing it does **not** change | Anything in the app UI | Anything about this repo's participation in a `wtd` fleet |

They are not two views of one dataset. Nothing reads both.

## The wtd fleet manifest — `fleet.manifest.yml`

`fleet.manifest.yml` is **this repository's entry in a `wtd` fleet**. It is an
outward-facing description: it tells fleet tooling that lives outside this repo
what this repo is and how to work with it. It uses the `fleet/v1` vocabulary and
is generated by `wtd fleet adopt`; per the project README, hand edits to it
survive regeneration.

Think of it as this repo's ID card. It says nothing about the GitFactory
application's behaviour, and the frontend never loads it.

**Edit this file when:** you are changing how `wtd` fleet tooling sees *this*
repository.

**Do not edit this file when:** you want the Fleet Ops cockpit to show a
different set of repositories. It has no effect there.

## The Fleet Ops roster

Fleet Ops is the cockpit inside the GitFactory frontend — the view that shows a
set of repositories and their factory-floor status. The set of repositories it
shows is the **roster**.

The roster is **not stored in this repository.** It is imported from a *hub*
repository's `.gitmodules` file: the hub repo tracks the fleet's repositories as
git submodules, and Fleet Ops reads that submodule list to learn who is in the
fleet. The engines that consume the roster (facts, metrics, audit) live under
[`app/src/fleet/`](../app/src/fleet).

So the roster's source of truth is *someone else's `.gitmodules`*. To change what
the cockpit lists, you change the hub repository's submodules — or point the app
at a different hub.

**Edit the hub repo when:** you want to add, remove, or reorder the repositories
the cockpit shows.

### Trying it without a hub

Opening the app with `?demo=1` runs the whole tool — canvas, prompts, telemetry
and the Fleet Ops cockpit — over a fictional three-repo fleet backed by fixtures,
with no token and no network calls. That is the fastest way to see what a roster
looks like without wiring up a real hub repository. Nothing is written to GitHub
in demo mode.

## "I want to change X — which file?"

| I want to… | Touch |
| --- | --- |
| Change what the Fleet Ops cockpit lists | The **hub repository's `.gitmodules`** (not this repo) |
| Change how `wtd` fleet tooling sees this repo | [`fleet.manifest.yml`](../fleet.manifest.yml) |
| Change how the roster is rendered or analysed | [`app/src/fleet/`](../app/src/fleet) |
| Change the demo fleet you see under `?demo=1` | The demo fixtures in `app/` |
| Change this repo's own automation | [`.factory/`](../.factory) — `blueprint.json`, `prompts/`, `config.yml` |

## Naming, and why it is like this

The collision is incidental: `wtd` is external tooling that happens to call its
unit of organisation a *fleet*, and Fleet Ops is a GitFactory feature that
happens to call its unit of organisation a *fleet* too. Neither name is likely to
change, so the mitigation is this page and the cross-links to it.

When writing about either concept, prefer the fully qualified names —
*"the wtd fleet manifest"* and *"the Fleet Ops roster"* — over bare *"the
fleet"*.
