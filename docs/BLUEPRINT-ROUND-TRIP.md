# The blueprint → compiled workflow round trip

> **The one-line version:** blueprints are source, `.github/workflows/factory--*.yml`
> are build artifacts. Edit the blueprint, never the workflow.

This document explains where a factory line is authored, what the compiler emits, and why hand-editing compiled output is a mistake that quietly undoes itself.

For the full compiler specification (auth phases, machine catalog, security model) see [`ARCHITECTURE.md`](ARCHITECTURE.md). For the authoritative inventory of every generated path and the determinism / action-pinning guarantees, see [`GENERATED-FILES.md`](GENERATED-FILES.md). This page is the narrative that ties them together.

---

## The round trip

```
  ┌─ SOURCE (you edit these) ────────────────────────────────┐
  │                                                          │
  │   .factory/blueprint.json      machines + belts          │
  │   .factory/prompts/*.md        agent prompt contracts    │
  │   .factory/config.yml          factory-level settings    │
  │                                                          │
  └──────────────────────────┬───────────────────────────────┘
                             │
                        ┌────▼────┐
                        │compiler │  app/src/compiler/
                        └────┬────┘
                             │
  ┌─ OUTPUT (never edit these) ──────────────────────────────┐
  │                                                          │
  │   .github/workflows/factory--*.yml                       │
  │       ↳ carries a GENERATED BY GITFACTORY header         │
  │                                                          │
  └──────────────────────────┬───────────────────────────────┘
                             │
                    GitHub Actions runs it
                             │
                             ▼
              Actions API telemetry read back and
              rendered as factory floor status in the app
```

The loop closes: the canvas is not a one-way exporter. It compiles down to YAML, and it reads run status back up from the Actions API. That is what makes an out-of-band edit to the YAML so easy to make and so easy to lose — the canvas has no idea you made it.

## Where the source lives

| Path | Role |
| --- | --- |
| `.factory/blueprint.json` | The machines and belts of this repository's own factory. Validated against [`schema/blueprint.schema.json`](../schema/blueprint.schema.json). |
| `.factory/prompts/*.md` | The prompt contract for each Claude agent machine. |
| `.factory/config.yml` | Factory-level configuration. |
| `examples/` | Example blueprints, shipped as documentation and as compiler fixtures. |

This repository dogfoods itself: `.factory/` is a real factory, not a sample. It is **source**, not output.

### The blueprint contract

`schema/blueprint.schema.json` is the contract a blueprint must satisfy. It is drift-guarded against the machine registry, so a machine type that exists in the registry but not in the schema (or vice versa) is a build-time error rather than a runtime surprise. If you are adding a machine, the schema is part of the change.

## What the compiler generates

| Path | Generated? | Notes |
| --- | --- | --- |
| `.github/workflows/factory--*.yml` | **Yes** | One file per compiled line. The `factory--` prefix is the marker. |
| `.github/workflows/` (everything else) | No | Hand-written CI, Pages and evolve workflows live alongside the generated ones. |
| `examples/compiled/` | **Yes** | Reference output that the compiler converges to for the blueprints in `examples/`. |

Generated workflows carry a `GENERATED BY GITFACTORY` header. **If a file in `.github/workflows/` has that header, it is output.** If you are unsure, check for the header before you touch it; the `factory--` filename prefix is a strong hint but the header is the truth.

The emitted YAML is deliberately plain and readable: it must be auditable, and it must keep working on a repository where GitFactory itself is not installed. That readability is a feature, and it is also the trap — a compiled workflow looks exactly like something you could edit by hand.

---

## The DO-NOT-EDIT rule

> **Never hand-edit a file that carries the `GENERATED BY GITFACTORY` header.**

Compiled workflows are regenerated **in place**. The compiler overwrites the file from the blueprint; it does not merge, it does not diff, and it does not warn you that your careful two-line fix is about to be erased. The next person who presses **Compile** — or the next automated regeneration — deletes your change, and the only trace is a confusing diff in an unrelated PR.

Worse, the edit *works* in the meantime. The workflow runs, does the thing you wanted, and everyone concludes the blueprint says what the YAML says. It doesn't. The canvas and the repository have silently diverged, and the divergence is discovered at the least convenient moment.

### What to do instead

| You want to… | Change this |
| --- | --- |
| Change a trigger, schedule or filter | The machine's configuration in `.factory/blueprint.json` |
| Change what an agent is told to do | The corresponding file in `.factory/prompts/` |
| Add or remove a step in the line | The machines and belts in the blueprint |
| Change something the blueprint cannot express | The compiler in `app/src/compiler/` — then regenerate |
| Change hand-written CI | Edit `.github/workflows/*` directly, as long as it has no generated header |

If the blueprint genuinely cannot express what you need, that is a compiler gap. File it in [`BACKLOG.md`](../BACKLOG.md) as a `BL-*` item rather than patching around it in the output — a workaround in generated YAML is a workaround with a timer on it.

## Recovering from an accidental hand-edit

If you (or a reviewer) spot changes to a generated workflow in a diff:

1. **Work out what the edit was trying to achieve.** The intent is the valuable
   part; the YAML is disposable.
2. **Express that intent in the blueprint** — machine config, belt topology, or
   prompt file — or in the compiler if the blueprint cannot say it.
3. **Regenerate** and confirm the compiled output now contains the intended
   behaviour on its own.
4. **Discard the manual edit.** Do not keep it "just in case": a generated file
   that differs from what the compiler would produce is a landmine.

If the regenerated output differs from the committed output in ways you did *not* intend, that is real information — it means someone edited by hand earlier, or the compiler changed. Investigate before committing.

---

## Review checklist

When reviewing a PR that touches `.github/workflows/`:

- [ ] Does any changed file carry the `GENERATED BY GITFACTORY` header?
- [ ] If yes, is there a corresponding change to `.factory/` or `app/src/compiler/`
      that explains it? A generated file changing *on its own* is the smell.
- [ ] Does the blueprint still validate against `schema/blueprint.schema.json`?
- [ ] If the compiler changed, was `examples/compiled/` regenerated to match?
