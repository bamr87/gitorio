# Regenerating compiled workflows

> **Short answer:** if CI fails because the compiled workflows have drifted,
> re-run the compiler, review the diff, and **commit the regenerated files**.
> Never fix the drift by editing `.github/workflows/factory--*.yml` by hand.

This page is the runbook for that failure. For the full picture of what the
compiler writes and the determinism/action-pinning guarantees behind it, see
[`GENERATED-FILES.md`](GENERATED-FILES.md).

## Source vs. output

This repository dogfoods GitFactory: its own automation is a blueprint that
compiles into its own workflows.

| Path | Role | Edit by hand? |
| --- | --- | --- |
| `.factory/blueprint.json` | The blueprint — machines and belts | ✅ Yes, this is the source |
| `.factory/prompts/*.md` | Agent prompt contracts | ✅ Yes, this is the source |
| `.factory/config.yml` | Factory configuration | ✅ Yes, this is the source |
| `.github/workflows/factory--*.yml` | **Compiler output** | ❌ **No** |

Every compiled workflow carries a `GENERATED BY GITFACTORY` header. That header
is the contract: anything under it is derived, and the next compile will
overwrite whatever you typed there.

The hand-written CI, Pages, and evolve workflows also live in
`.github/workflows/` and are *not* generated — the `factory--` filename prefix
and the header are how you tell them apart.

   ```bash
   git add .factory .github/workflows
   git commit -m "..."
   ```

4. **Push.** CI recompiles and compares; a clean tree means no drift.

It recompiles into a scratch location and compares against what is committed,
without touching your working tree. A non-zero exit means you owe the repo a
regenerate-and-commit; go back to the steps above.

Running it as part of your pre-push habit — next to `npm test` and
`npm run typecheck` in `app/` — is the cheapest way to keep the blueprint and
its compiled output honest.

## Why not just hand-edit the YAML?

Because the compiled workflows are meant to be readable and auditable *and*
reproducible. A hand edit survives exactly until the next compile, and in the
meantime the repository claims a blueprint that does not describe what is
actually running. If the YAML needs to say something different, the change
belongs in `.factory/` — or, if the compiler cannot express it, in the compiler
(`app/src/compiler/`) with a backlog item behind it.
